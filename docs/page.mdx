# Introduction

**NestJS TypeORM AWS Connector** resolves TypeORM configuration from AWS Systems Manager Parameter Store and credentials from AWS Secrets Manager while keeping one stable Nest-injected `DataSource`.

Connector 3 runs on NestJS 12, TypeORM 1 and Node.js `^22.13.0 || >=24.11.0` and ships as ES modules only; see [Migrating to 3.0](/docs/nestjs-typeorm-aws-connector/guides/migrating-to-3-0). Since Connector 2 it has a bounded credential-rotation lifecycle:

- one current and at most one retiring pool;
- query-runner and manager-bound transaction affinity;
- coalesced intervals instead of queued replacement pools;
- a required positive shutdown drain timeout when rotation is enabled;
- package-neutral deferred, retired, and timeout events;
- bounded best-effort shutdown with aggregate failure reporting.

## Ownership boundary

The connector owns AWS lookup, replacement verification, driver promotion, generation accounting, and shutdown cleanup. The consuming application owns:

- the rotation interval and shutdown budget;
- whether each runtime role enables periodic rotation;
- the observability adapter passed through `rotation.onEvent`;
- host-orchestrator termination budgets and alert policy;
- database capacity for the temporary current-plus-retiring overlap.

The event callback is observability only. It must not control rotation, perform database writes, or contain credentials.
